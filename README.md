# Telegram-бот ресторана

Учебный проект на Python и aiogram 3. Интерфейс для клиентов — на русском языке. Существующие категории и идентификаторы каталога сохранены. **Цены каталога указаны в сомони**, потому что исходный каталог и требования к итоговой корзине используют сомони; переменная `CURRENCY` меняет только подпись и не конвертирует цены.

## Требования
- Python 3.10 или новее (рекомендуется Python 3.12).
- Аккаунт Telegram и токен бота от [@BotFather](https://t.me/BotFather).

## Установка
```bash
git clone https://github.com/cosmos634/restoran_bot.git
cd restoran_bot
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` в редакторе и вставьте значение `BOT_TOKEN`. Не публикуйте файл и не отправляйте токен в сообщениях или скриншотах. Если токен когда-либо попал в публичный репозиторий, немедленно отзовите его через @BotFather и создайте новый: удаление файла не аннулирует токен и не очищает Git-историю.

## Настройки
- `BOT_TOKEN` — обязательный токен бота.
- `ADMIN_IDS` — необязательные Telegram user ID администраторов через запятую, например `123456789,987654321`.
- `RESTAURANT_NAME` — название ресторана в приветствии.
- `DATABASE_PATH` — путь к SQLite-файлу, по умолчанию `restaurant.db`.
- `CURRENCY` — подпись валюты, по умолчанию `сомони`. Цены не пересчитываются при смене этой подписи.

## Запуск
```bash
python main.py
```
Бот работает через polling, поэтому отдельный веб-сервер не нужен. На хостинге добавьте переменные окружения в настройки сервиса. Убедитесь, что SQLite-файл хранится на постоянном диске: временный диск может потерять заказы после перезапуска или нового развёртывания.

## Проверки
```bash
pytest -q
python -m compileall -q .
```
Тесты не требуют токена Telegram или сетевых запросов.

## Изменение каталога
Редактируйте `data.py`: у каждого товара есть `name`, `description` и `price`. По возможности не меняйте идентификаторы категорий и товаров, поскольку на них завязаны кнопки и сохранённые корзины.

## Реализовано
- Просмотр пицц, бургеров и напитков.
- Корзина в SQLite, изменение количества, безопасное удаление и очистка с подтверждением.
- Оформление через FSM: имя, телефон или собственный Telegram-контакт, доставка/самовывоз, адрес и подтверждение.
- Заказы и позиции сохраняются в SQLite; история изолирована по Telegram ID.
- Повторное подтверждение с тем же ключом не создаёт второй заказ.
- Необязательные уведомления администратору и изменение статуса заказа при заданном `ADMIN_IDS`.
- Оплата наличными при получении. Онлайн-платежи не подключены.

## Ограничения
- FSM хранится в памяти и сбрасывается при перезапуске; корзины и заказы в SQLite сохраняются, но оформление после перезапуска нужно начать заново.
- Для нескольких экземпляров приложения понадобится общий устойчивый FSM storage и общее постоянное хранилище.
- Без `ADMIN_IDS` бот продолжает принимать заказы, но не уведомляет администраторов.
- Кнопка контактов пока содержит заглушку. Перед показом реальному ресторану замените её на настоящий контакт.
