# Restaurant Telegram Bot

Небольшой Telegram-бот ресторана на Python и aiogram 3. Каталог сохраняет существующие категории и идентификаторы товаров; цены каталога сейчас указаны в сомони.

## Требования
- Python 3.10 или новее (рекомендуется Python 3.12).
- Telegram-аккаунт и токен бота от [@BotFather](https://t.me/BotFather).

## Установка локально
```bash
git clone https://github.com/cosmos634/restoran_bot.git
cd restoran_bot
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` в редакторе и заполните `BOT_TOKEN`. Никогда не отправляйте этот файл в GitHub и не показывайте токен в скриншотах. Если токен когда-либо был опубликован, отзовите его через @BotFather и создайте новый.

## Настройки
- `BOT_TOKEN` — обязательный токен бота.
- `ADMIN_IDS` — необязательные Telegram user ID администраторов через запятую, например `123456789,987654321`. Узнать собственный ID можно через надёжного Telegram-бота; не указывайте чужой ID без разрешения.
- `RESTAURANT_NAME` — название ресторана в приветствии.
- `DATABASE_PATH` — путь к SQLite-файлу, по умолчанию `restaurant.db`.
- `CURRENCY` — подпись валюты, по умолчанию `сомони`. Цены существующего каталога заданы в сомони; при смене подписи сами цены не конвертируются.

## Запуск
```bash
python main.py
```
Бот использует polling, поэтому отдельный веб-сервер не нужен. Для хостинга добавьте те же переменные окружения в панели платформы. Постоянное хранение файла SQLite должно быть включено на выбранном хостинге; эфемерный диск может потерять заказы при перезапуске.

## Тесты
```bash
pytest -q
python -m compileall -q .
```
Тестам не нужны Telegram-токен или сетевые вызовы.

## Где менять каталог
Откройте `data.py`. Для каждого товара редактируются `name`, `description`, `price`. Идентификаторы категорий и товаров лучше сохранять, потому что на них опираются callback-кнопки и данные корзины.

## Что реализовано
- Категории пицц, бургеров и напитков; просмотр товаров.
- Изолированные SQLite-корзины, изменение количества, очистка с подтверждением.
- Оформление через FSM: имя, телефон/контакт, доставка или самовывоз, адрес, проверка и подтверждение.
- Заказы и позиции заказа сохраняются в SQLite; история доступна только владельцу Telegram ID.
- Повторное подтверждение с тем же ключом не создаёт повторный заказ.
- Необязательные уведомления и изменение статуса для `ADMIN_IDS`.
- Оплата только наличными при получении; платёжный провайдер не подключён.

## Ограничения
- FSM-состояние хранится в памяти и сбрасывается при перезапуске; уже сохранённые корзины и заказы в SQLite остаются. Пользователь при необходимости начнёт оформление заново.
- Для production с несколькими экземплярами нужен общий устойчивый storage для FSM и общий постоянный диск/база данных.
- Если `ADMIN_IDS` не задан, бот принимает заказы, но уведомления администратору не отправляются.
- Контакт ресторана пока является текстовой заглушкой; добавьте реальный контакт в `handlers/callbacks.py` перед демонстрацией заказчику.
